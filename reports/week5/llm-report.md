# Week 5 LLM Usage Report

**Project:** LAMBA  
**Team:** Team 22  
**Sprint:** Sprint 3 / Assignment 5  
**Tool used:** ChatGPT

## 1. Purpose of LLM usage

During Assignment 5, the team used ChatGPT as a supporting tool for documentation work. The LLM was not used as an independent source of project facts and was not treated as an authority on the actual state of the repository, product, Sprint Backlog, implementation, or customer feedback.

The main purpose of using ChatGPT was to help improve and finalize already existing materials. The team provided the actual project context, meeting transcript, assignment requirements, links, and repository evidence. ChatGPT was then used to help clean up wording, structure Markdown files, translate or rewrite rough notes into clear English, and make the documentation easier to read.

## 2. Artifacts supported by LLM

ChatGPT was used to support the preparation and refinement of Week 5 reporting artifacts, including:

- cleaning and organizing the Sprint Review transcript;
- preparing the Sprint Review summary from the recorded meeting transcript;
- improving the structure and wording of report files;
- helping align documentation with the Assignment 5 checklist;
- preparing or refining short explanatory sections for the public Week 5 report and Moodle submission materials.

The LLM helped with formatting, wording, summarization, and consistency. The actual Sprint content, customer feedback, team decisions, product scope, and implementation evidence came from the team and from repository artifacts.

## 3. Human verification

Every LLM-generated or LLM-edited output was manually reviewed by the team before being accepted. The team checked that:

- the content matched the real Sprint Review discussion;
- customer feedback was represented accurately;
- the described MVP v2 scope matched the actual project work;
- links, issue references, PR references, and repository evidence were not invented;
- the wording did not add unapproved claims about implemented features, tests, CI, hosted documentation, or releases;
- private information was kept out of public repository artifacts where required.

When the LLM output contained wording that was too broad, too confident, or not supported by project evidence, the team corrected it manually or asked for a revised version.

## 4. Limitations and corrections

The team treated ChatGPT output as draft text, not as final evidence. The LLM could not know the actual repository state, the final merged PRs, the final release links, or private recording details unless the team provided them. Because of that, the team avoided relying on ChatGPT for factual claims without checking them.

The main limitations were:

- generated wording sometimes needed to be made more precise;
- some sections required additional project-specific facts from the team;
- private and public evidence needed to be separated manually;
- transcript-based summaries needed human review to make sure the customer’s feedback was not misrepresented.

## 5. Scope of responsibility

The team remained responsible for all final submitted artifacts. ChatGPT helped with editing, structure, cleanup, and consistency, but the team made the final decisions about what to include, what to remove, and what evidence was valid.

The final documentation reflects the team’s own Sprint work, customer review, UAT discussion, architecture documentation, and repository evidence.
